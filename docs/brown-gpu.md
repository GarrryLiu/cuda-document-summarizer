# Brown GPU experiment — 2026-10-27

Executed through Brown's Slurm `gpus` partition, one L40 allocation, 4 CPU cores,
24 GB host RAM, 30-minute limit. The source was transferred from the local
checkout; dependencies and model weights were installed in a node-local temporary
directory because the home filesystem was nearly full. No existing coursework
files or environments were changed.

Environment: NVIDIA L40 (46,068 MiB), Python 3.12.3, torch 2.14.1+cu130,
Transformers 4.57.6, FP16. Exact packages are in
`experiments/gpu-environment.txt`. Model revision:
`aa8e72537993ba99e69dfaafa59ed015b17504d1`.

## Short-document smoke test

Input: `data/example.jsonl`, two fictional reports. Batch size 2, output cap 128
new tokens, 3 measured repeats per condition, longest-batch warm-up. Both
ordering policies place the same two documents in one batch, so no padding
speedup is expected. All four configurations completed successfully.

| Ordering | Cache | Median docs/s | Median generated tokens/s | Max allocated GiB |
|---|---|---:|---:|---:|
| arrival | off | 0.440 | 45.8 | 5.91 |
| arrival | on | 0.447 | 46.4 | 5.89 |
| length | off | 0.439 | 45.6 | 5.91 |
| length | on | 0.448 | 46.6 | 5.89 |

Raw per-repeat metrics and generated summaries:
`experiments/gpu-smoke-results.json`. Nine unit tests also passed on the cluster;
see `experiments/brown-logs/tests.log`.

A spot check of the arrival/cache-off outputs revealed two quality issues: the
first summary ends mid-sentence at the 128-token cap; the second says quantitative
findings were not reported despite the source reporting that all 100 events
remained available. These outputs establish runnable inference, not acceptable
summary quality. Longer generation and a source-backed evaluation are needed.

## Reproduction on Brown

From a source checkout on the cluster, run:

```sh
sbatch scripts/brown-gpu.sbatch
```

The template uses the same resource request and smoke parameters. It assumes `uv`
is already on PATH. It places caches in `/tmp`, saves results to the submitted
checkout, and prints the cache directory for explicit cleanup. The recorded run
used an interactive `srun` allocation with equivalent resources. The batch script
itself has not been submitted. Check available resources and storage before a
larger run; no new long-lived cluster environment is required.

Measurements include CPU/GPU transfers and generation, and exclude model load,
tokenization, warm-up and summary text decoding. Fixed condition order, only three
repeats and a shared cluster node limit inference about performance. No confidence
interval, online latency, real-report factuality score or general speedup is claimed.

## Controlled mixed-length GPU experiment

Input: `data/controlled.jsonl`, eight explicitly fictional repeated-paragraph
reports generated by `experiments/make_controlled.py` (seed 42). Actual prompt
lengths, including the chat template, are 328–3,688 tokens; the result stores each
length. Local and remote input SHA-256 hashes were verified equal. Batch size 4,
32-token generation cap, three repeats and per-condition warm-up. All four
conditions completed. The short cap is for a scheduling exercise; these outputs
are not complete summaries and were not scored for quality.

| Ordering | Cache | Median docs/s | Median generated tokens/s | Max allocated GiB |
|---|---|---:|---:|---:|
| arrival | off | 0.170 | 5.4 | 7.07 |
| arrival | on | 2.209 | 70.7 | 7.56 |
| length | off | 0.190 | 6.1 | 7.07 |
| length | on | 2.318 | 74.2 | 7.56 |

At cache-on, length ordering improved median document throughput by **4.95%**
versus arrival ordering in this specific workload. Padded input allocation fell
from 20,544 to 17,856 positions (13.08% lower). Within arrival ordering, cache-on
was about **13.0×** the median throughput of cache-off. This is an ablation against
explicitly disabling the standard Transformers KV cache, not an improvement over
an already cached production baseline. Cache-on increased peak allocated memory.

Per-repeat cache-on document throughput was 2.2065, 2.2085, 2.2164 for arrival and
2.3195, 2.3179, 2.3141 for length ordering. The fixed condition order, small
synthetic fixture, repeated prose and short decode cap limit generalization.
Neither this result nor the padding-only simulation supports a 25% general
summarization throughput claim.

Raw measurements and generated outputs:
`experiments/gpu-controlled-results.json`. Reproduce after creating the input:

```sh
python3 experiments/make_controlled.py
PYTHONPATH=src python3 -m cuda_summary.benchmark \
  --input data/controlled.jsonl --batch-size 4 --max-new-tokens 32 \
  --repeats 3 --revision aa8e72537993ba99e69dfaafa59ed015b17504d1 \
  --output experiments/gpu-controlled-results.json
python3 experiments/summarize_gpu.py experiments/gpu-controlled-results.json
```

Both runs used the model revision above and the frozen environment. Logs are in
`experiments/brown-logs/`. Node-local files were removed after local retrieval;
the interactive GPU allocation was released.
